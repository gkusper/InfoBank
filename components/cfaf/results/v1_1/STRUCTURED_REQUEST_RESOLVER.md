# Structured request resolver v1.1

The resolver is a small injected component, not a general NLP parser. The field registry supports file/document type, creation date/year/time and modification date/time. Metadata is still an access class; field values are separately checked as strings or ISO dates/times. Every requested field must be present and permitted; unsupported extra fields and unavailable precision prevent deterministic FULL.

Trusted target aliases come from the authenticated application policy result, or the existing application catalogue title. A small display-suffix normalization handles catalogue labels such as metadata cards and summary reports. No benchmark IDs or entity names are in the rules. Exact target matching is required; duplicate/near-prefix targets remain unresolved. Hidden and denied sources never enter the target inventory. Bindings include principal, purpose, policy/revocation version and integrity/request signatures, and are revalidated before use. A policy-current callback also runs before and after inference/publication.

New natural-language aggregate zero-call execution requires known operation, explicit registered metric and unit, population, contributor IDs, finite numeric values, row authorization, privacy threshold and requested period. The existing pure aggregate executor performs contributor deduplication and threshold enforcement. Requested-year execution requires row dates and the matching full-year scope. The visible authorized structured snapshot must agree with the independently recomputed operation/result/metric/unit/population. COUNT additionally needs a countable-metric attestation; SUM/MEAN cannot be replaced by counting numeric rows. No value is extracted from arbitrary prose.

An authorized precomputed prose aggregate is not a trusted numeric table. A uniquely bound COUNT question can use it as evidence in the ordinary single-call path; support remains MODEL_ATTRIBUTED and passes the normal requirement/type/role gate. It never receives APPLICATION_STRUCTURED provenance. This distinction is necessary for the existing InfoBank aggregate fixture, whose legitimate input has no numeric row/metric contract.

The pre-existing literal metadata[field]/aggregate[operation] compatibility API remains available for a single application-authorized snapshot. It retains v1's trust in upstream application validation of that snapshot; it does not independently reconstruct missing population/threshold provenance. Use the new typed row contract when local verification of those properties is required. Model proposals cannot create either kind of trusted binding. The new natural-language route never silently turns a prose number into a trusted structured operation.

Only conservative scoped expressions are recognized. Ambiguity/incomplete metadata/metric/unit/period yields safe CFAF, or the ordinary evidence path where appropriate. Catalogue normalization, the memory quota and callback policy service remain application-integration assumptions, not independent source authentication. Synthetic examples and the five-path runnable demo use fictional data only.
