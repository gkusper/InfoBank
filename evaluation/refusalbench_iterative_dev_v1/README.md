# Bounded iterative CFAF development

Three fresh balanced development rounds (10 FULL + 10 CFAF each) compare immutable implementations v00, v01 and v02. A separate paired regression evaluates v02 on exactly the already-exposed twenty round-01 inputs. The paired run adds no record exposure. Read REPORT.md, per-round error_analysis.md/diagnostics.json, source_version.json and the global exposure ledger before interpreting scores.

The task has one persistent monotonic start time and a strict 60-minute limit in time_limits.json. deadline.py rejects work likely to exceed the remaining window, prioritizes reporting at 50 minutes, and rejects new API calls from 55 minutes. Every API request checks that guard and the durable global 360-attempt ledger immediately before HTTP; request timeout is 45 seconds. Bounded test subprocesses use the remaining deadline as an upper timeout. test_budget_deadline.py verifies cutoff and budget behavior without network use.

exposure.py reconstructs all available local branch selection manifests and previous selected-case artifacts. Initially 82 unique official record IDs were known exposed, 70 in the 1234-case non-contradiction pool. The ceiling is 617 eligible IDs. Fifty-two already-exposed source groups are authorized; thirty reserved and eighteen untouched groups remain forbidden. New IDs are charged durably BEFORE passage materialization, and selected without replacement with seeds 20261028/29/30 and exact 2-per-refusal-category quotas. Every round uses twenty distinct source groups. Never reset the ledger to create apparent capacity. Future development must inherit every exposure in this ledger and later selections.

The original pinned official file remains read-only, SHA-256 d1bddaec4fdb7e0e2e7bf9a520ef104c3758800fc16769ac6e34baef0d90d1ed. Filtering matches the earlier exact-word contradiction rule and the two exact category exclusions; metadata-only inspection does not materialize reserved/untouched queries or contexts. Only selected cases are saved as full trusted annotations. Model workers read exactly the authorized perturbed_query and perturbed_context rows, neutral IDs, and derived profiles/assessments. Source IDs, expected labels, original answers, explanations and other annotations are scorer/preparation-only.

Version v00 imports the unchanged InfoBank semantic-integration-v2.1. v01 adds general factual query/answer typing, specific internal reasons and bidirectional mode/status validation while retaining original governance types and the unchanged top-level selector. v02 adds per-requirement completeness, identity/relation/qualifier checks, referent resolution and a constrained query-only fallback for otherwise unresolved questions. The fallback has no context or answer/mode field; copied query spans and a query-bound validated profile are checked before use. It costs an additional request only when used, is skipped with no permitted evidence and remains explicitly uncertain where needed. Governance projection, metadata authorization/revocation, spans and eight-stage execution are preserved.

The original provider.py/runner.py and newer provider_v2.py/runner_v2.py coexist so earlier frozen rounds are not overwritten when fallback support is added. Each round preserves frozen_source copies, source hashes, prompts and strict schemas. External primary scoring in scoring.py is identical across versions, including ERROR for cross-field contradictions. One generator's invalid output does not invalidate its valid peer. Invalid outputs are retained, never repaired. This rule differs from the older non-contradiction pilot's one-way validation; historical comparisons must respect that protocol difference.

Reproduction uses the frozen inputs/code snapshots; a completed run refuses overwrite. New experiments require new output directories, cumulative exposure accounting and a new task-wide deadline/budget. Do not simply reinitialize an old ledger. Typical stages in a new authorized study are:

- `python -m evaluation.refusalbench_iterative_dev_v1.exposure` (initial reconstruction only if no ledger exists).
- Run the relevant version tests and original InfoBank regressions in a disposable exact-Git-blob checkout.
- `python -m evaluation.refusalbench_iterative_dev_v1.runner prepare --round 1 --version v00`, then `...runner generate --directory round_01`.
- `...runner prepare --round 2 --version v01`, then generate round_02.
- `...runner_v2 prepare --round 3 --version v02`, then generate round_03.
- `...runner_v2 paired --version v02 --baseline round_01`, then generate paired_regression.
- `python -m evaluation.refusalbench_iterative_dev_v1.audit` and the report assembler.

OPENAI_API_KEY is supplied only through the environment. Requested model is gpt-4o-mini, temperature 0, one repetition, generation limit 160 and main semantic-analysis limit 1500; fallback limit 500. There are no embeddings, automatic retries or extra answer-judge calls. All raw requests/events are durable. Source/reference validity is not semantic entailment, copied candidates are not necessarily complete answers, and adaptive development scores are not independent validation. No significance tests or automatic official-label corrections are performed.

The exact changed-file inventory and artifact hashes are CHANGED_FILES.txt/checksums.sha256. All previous repository files are protected by protected_files.json. Final completion time including the local commit is recorded separately in the outputs completion receipt; the committed report records its preparation time and points to that receipt. No push or merge is performed.
